# Blocks and reader behavior

Choose by teaching job: `def` for a substantial concept, `key` for a reusable
rule/procedure, `ex` for a worked case, `p` for context and connections, `trap`
for a concrete error. `note` is supplementary only with `optional: true`.
Other shapes: `list`, `table`, `code`, `math`, `figure`, `image`, `slides`, `attempt`.
See formats/blocks.md for syntax and compact capabilities.

Keep a coherent explanation or worked case together, with a specific title.
Start a unit when the concept or job changes; minor terminology can stay inline.
Use labeled items/tables for parallel cases and `ordered: true` for sequential
reasoning. Each unfamiliar step needs its action and reason. Comparisons
consolidate ideas already introduced.

Figures, tables and images need explanatory captions; images need useful `alt`.
Prefer data figures when feasible. Connect each representation to the nearby
reasoning: establish unfamiliar labels/assumptions, trace a meaningful case, and
interpret the result. A subject-name caption is insufficient.

Formatting: formats/inline.md. Optional attachments: formats/depth.md.
The reader hears headings, prose, list items, definitions and captions, but not
figure bodies, table cells, code, formulas or quiz answers. State spoken results
in prose. Course CSS is restricted to declared classes and allowed properties.
