# Learner and scope

The learner knows algebra, single-variable calculus, matrix multiplication,
determinants, and the definition of an eigenvalue. The learner has **not**
studied differential equations, phase portraits, Laplace transforms, gateway
architecture, caching, distributed systems, or measurement design. Define a
technical term before using it unless it is in that background.

Write a substantial eight-lesson course sample in this order. The two strands
have separate readers with the same listed background; do not imply the math
strand is a prerequisite for the systems strand.

| ID | First teaching job | Later use |
| --- | --- | --- |
| M1 | Verify a differential-equation solution and interpret initial data | M2–M4 |
| M2 | Forced oscillation and exact undamped resonance | Later forcing decisions |
| M3 | Repeated eigenvalues, missing eigenvectors, and system trajectories | Later matrix methods |
| M4 | A switched-on input and continuity at the switch | Later piecewise forcing |
| S1 | Define units, denominator, baseline, and counterfactual | S2–S4 |
| S2 | Explain a request gateway and where tokens or cost can change | S3–S4 |
| S3 | Design a safe full-response cache and explain its failure modes | S4 |
| S4 | Defend a quantified resume-style claim without inventing evidence | Future interviews |

The mathematics assessment is closed-resource, written, and includes method
selection, derivation, computation, and error spotting. The systems assessment
is an interrupted verbal interview with follow-up questions. A learner must be
able to transfer to new numbers and arrangements, not recite the worked case.

Priority: correctness, source honesty, teachable steps, and meaningful visuals.
Length is a floor for developing ideas, not a reason to pad. Each lesson should
be complete enough that a reader could study it independently in sequence.
