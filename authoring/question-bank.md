# Bank inventory and review

Types define distinct methods/decisions once, using approved concept, objective
and family IDs. Teaching/prerequisite links serve help and diagnosis without
locking advanced work. Sparse assessment requirements derive the full blueprint;
review scoring ownership, representativeness and source coverage explicitly.
Never infer exam weight from item counts or duplicate inherited item metadata.

Batch related types and practice/reserved siblings together. Writer verification
covers every answer. Review every distinct method/group, exceptional branch
and flagged risk independently; use reviewed deterministic checks only for
truly equivalent siblings. Read shared context once. Expand selected IDs and
exact source spans only when needed. Type packets include sibling answers and
linked teaching. Shortages, duplicates and group labels are leads, never proof
of sufficiency or independence. Record current blueprint/mapping judgment in
the existing consolidated review. Paired reviewers judge and issue corrections;
writers handle formatting and changes. The same boundary applies to auto and
manual handoffs. Single mode retains all checks with one agent.

For unplaced section/course tasks or category teaching anchors, use the existing
`packet --ids type-<id>,type-<related-id> --phase write` after `index`; this groups
related type definitions and siblings in one writer packet. Lesson packets
include their placed/taught types automatically. Do not create per-item calls
or a separate production pipeline for unplaced items.
